# MasterMe — Backend

MasterMe API and worker. The backend transforms technical materials into navigable concepts, evaluates explanations by concept, and generates practice projects with deterministic focus. It uses the official `@google/genai` SDK, structured output validated by Zod and explicit context; does not use RAG, embeddings, LangChain or LangGraph.

## Access

- Health check: <https://masterme-api.duckdns.org/health>
- Frontend Repo: <https://github.com/J-V-S-C/MasterMe-Front>

The public domain is served by Caddy on OCI, which terminates HTTPS and forwards the requests to the API available only at `127.0.0.1:3333` on the VPS.

## Run

```bash
# configure GEMINI_API_KEY and SUPABASE_URL in the private .env file
docker compose --env-file .env --env-file .env.development up --build
```

The local Compose mounts the backend source and runs API and worker with Bun watch mode. After the first startup, edits to backend TypeScript files restart the affected process automatically. Rebuild the image when dependencies, the Prisma schema, or Dockerfile change; those files are not hot reloaded.

For extraction failures, run `docker compose --env-file .env --env-file .env.development logs worker`. The `extract-material` record includes the processing stage, attempt, retry decision, safe failure reason, and any available application code, HTTP status, system code, or source location. It deliberately excludes raw provider messages, uploaded content, and student or material IDs. An older entry containing only `EXTRACTION_FAILED` cannot reveal the exact underlying exception; the material status can still show the student-facing failure and the job's last stage.

Local validation:

```bash
docker compose --env-file .env --env-file .env.development up -d test-db
bun install
bun run validate
```

Install the versioned pre-commit hook once per clone with `git config --local core.hooksPath .githooks`. It runs `scripts/ci-local.sh` before every commit: PostgreSQL integration tests, dependency audit, production Compose validation, image build, and image smoke test. Keep Docker running and stage all changes before committing; a failed gate aborts the commit.

## Architecture

Target architecture is a modular DDD-oriented monolith. In each module, HTTP validates and translates errors; application coordinates usage cases and transactions; domain protects invariants without relying on frameworks; infrastructure implements ports for PostgreSQL, SDKs, files and queue; `main` composes API and worker. Modules do not depend on each other's internals. Aggregates with lifecycle encapsulate transitions; snapshots, DTOs and external inputs use Zod. Do not create abstractions or classes without current business rule.

Prisma ORM was chosen for persistence, with incremental migration of adapters and baseline compatible with existing schema. Types generated by the ORM do not cross to domain or HTTP; safe SQL remains allowed for locking and specific queries. OpenAPI accompanies every change of contract. The OpenTelemetry, Prometheus and Grafana stack is the chosen direction for observability; instrumentation, collection, storage, dashboards and alerts will only be delivered when they operate together. The list below describes the current state, not the completion of this architectural or operational migration.

`prisma/migrations/` is the only source of the SQL migration files. The `bun run migrate` command reads these files and preserves the names and checksums of the ledger already existing in the production database; do not run `prisma migrate deploy` in this database without first reconciling Prisma's history with this ledger. The migration of adapters to Prisma Client is gradual and does not change this rollout rule. `dev/postgres-init.sql` creates only the `auth.users` table that Supabase already provides for the local PostgreSQL Compose. `docker-compose.yml` is the local environment; `deploy/compose.yml`, `deploy/.env.example` and the deploy script are the deployment manifest and configuration of the production VM, with its own limits and secrets. `test-fixtures/phase2/` contains small materials and representative reference PDFs to test parsers, provenance and compatibility; the documentation describes the expected result, but does not replace these reproducible input data. PDFs are extracted by `pdftohtml` from Poppler in subprocess with timeout, virtual memory limit, output limit and 800 pages maximum; the Dockerfile installs `poppler-utils` and includes `prlimit`. Outside the container, install Poppler and `prlimit` (util-linux) to test PDF upload. The XML SAX parser preserves only outline data that locates headings on the pages; without a reliable outline, the material remains a single unit.

- Express receives and validates parameters and bodies before controllers.
- Material kind (`BOOK`, `ARTICLE`, or `TEXT`) is inferred on upload or chosen by the student and can be corrected with `PATCH /api/materials/:id/kind`. Legacy rows keep an unset kind and retain the previous extraction inference. `GET /api/learning/materials/:id/outline-state` returns the outline revision and original headings; `PATCH /api/learning/materials/:id/outline` sends the complete ordered list with an expected revision. Existing entries keep their IDs and source offsets; a new entry supplies a title and source offsets within the original text. Omitted entries are removed only when they have no chapter checkpoint or linked task. Migrations 031 and 032 are additive; rollback keeps their columns and historical data while disabling the new writes.
- `GET /api/learning/today` returns at most three time-fitting, explainable actions from today's scheduled tasks, due reviews, open gaps, and the next readable section. It never creates a task or changes learning evidence. The browser can override available minutes for the current session; the account's weekday availability is the default.
- `src/main/factories/` mounts repository → service → controller by resource; `src/infra/http/routes/` only associates middleware and handlers. The worker uses service factories rather than HTTP controllers.
- Repository contracts stay in `src/application/repositories/`; external gateways stay in `src/application/ports/`. Adapters PostgreSQL and in memory stay in `src/infra/repositories/`. The memory implementation only serves the tests.
- Named service API interfaces and types are in `src/application/contracts/`, grouped by service; exclusive persistence types remain with the repository contract.
- Workspace 2.0 uses `LearningWorkspaceService` and a repository port in `src/application/`; Prisma, editorial parser, leases and transactions stay in `src/infra/repositories/prisma/prisma-learning-workspace.repository.ts`. CRUD operations are still routed by the service and the transactional suggestion decision remains in the adapter; refining these contracts is an outstanding architectural migration.
- `server.ts` chooses the process; `src/main` composes API/worker and `src/infra/http/app.ts` configures middleware and routers.
- `StudySessionAggregate` and `BillingOrderAggregate` protect part of the domain's invariants; migration of the other flows is still underway.
- `PracticeFocusService` is a pure domain service that orders focus without calling AI; `MasterMeService` still concentrates legacy use cases.
- Repositories in PostgreSQL and memory isolate persistence and testing.
- `GeminiMasterMeGateway` extracts concepts, evaluates answers and generates only the textual fields of the Practice Project.
- Upload and extraction use PostgreSQL queue, separate worker and SSE progress.
- SSE uses `LISTEN/NOTIFY` to wake up connections and the event table for replay after reconnection; there is no database query every second per client.

## Observability

`/health` is liveness without dependencies; `/ready` checks the database with timeout and is the gate of deploy. `/metrics` displays RED, AI, credits, queue and billing in Prometheus format only with an operational bearer token and is disabled (`404`) without configuration. Labels use enums and route templates, never IDs or content. Memory counters restart with the process; queue gauges and AI aggregates/credits from the last 24 hours come from the database. The current Prometheus endpoint does not mean that Prometheus collection, Grafana dashboards, or OpenTelemetry tracing are running in production.

## Security, entitlements, and AI credits

- The free plan receives 100 credits/day, with no monthly ceiling. API period fields mirror the day for the Free plan to maintain compatibility. Essential receives 120/day and 1,500 per 30-day period; Pro receives 180/day and 15,000 per 365-day period.
- Every real generation attempt on Gemini costs 1 credit, including fallback. The credit represents a request sent, not tokens or guarantee of capacity in the provider.
- Consumption is reserved atomically in PostgreSQL and complies with the daily limit, `AI_GLOBAL_DAILY_CREDIT_LIMIT` and the kill switch `AI_CREDITS_ENABLED`; paid entries also comply with the term limit.
- `GET /api/billing/me` is the authoritative source of balance. `GET /api/ai-usage/today` temporarily remains for call/token compatible telemetry only.
- A cache hit does not consume quota. The interface shows MasterMe's internal credit balance, which is independent of the project limits in Google AI Studio.
- The API limits global bursts by IP and applies a limit per user only on routes capable of consuming AI. Production should also keep rate limiting in Caddy/Cloudflare.
- The Gemini key remains only in the backend and must be exclusive, restricted and rotated.

## InfinitePay Recovery

- Empty `INFINITEPAY_HANDLE` is the free release mode: the catalog displays only `FREE`; checkout, HTTP rereconciliation and webhook respond `404`, and the reconciler does not run. `GET /api/billing/me` and credit reserves remain active. Activating payments requires configuring the provider and publishing the corresponding frontend in the same release.
- Essential (R$ 29.90/30 days) and Pro (R$ 249.00/365 days) are single payments without automatic renewal.
- Repurchases extend only the same tier. If Essential and Pro are active at the same time, Pro has priority and only its credits are consumed; essential validity and balance are neither promoted nor incorporated into the Pro.
- The frontend sends only `planId` and `Idempotency-Key`; price, description, redirects and webhook are defined by the backend from `PUBLIC_APP_URL`.
- The webhook is just a trigger. Entitlement is granted only after `payment_check` server-to-server confirm payment and value, with idempotent order, transaction, and entitlement records.
- Competing events are admitted atomically, with at most five pending events per order. The memory reconciler coalesces triggers and leases in PostgreSQL limit all replicas to five active events, up to one per request. `paid=false` closes that event; identical replay remains terminal and only a genuinely new signal creates another attempt.
- The API never receives or stores card data. Payment records hold only technical IDs, value, plan and state required for reconciliation.

## Practice project

The frontend displays only automatic focus and manual selection. As an internal contract and for compatibility, the generation body accepts `focusMode` equals `OVERVIEW`, `MANUAL`, `CONFIDENCE`, `PERFORMANCE` or `COMBINED`, as well as `conceptIds` when the mode allows. Ranking and reasons are calculated before Gemini. Modes without usable signals return `422` without hidden fallback. Semantically identical inputs use `practice_projects` cache.

## Cache and update in real time

- Stable private readings return `ETag` and `Cache-Control: private, max-age=0, must-revalidate`; volatile data, mutations, quota and SSE use `no-store`.
- Events are filtered by `owner_id`, persisted before notification and accept `Last-Event-ID` for safe replay.
- The listing of materials never includes the full text. Consumers must seek `/api/materials/:id` only for active material.

## Language and pedagogical evaluation

- New materials use `pt-BR` by default and accept `pt-BR` or `en-US`.
- Concepts, questions, diagnoses and projects are generated in the language of the material; the source excerpt remains literal.
- Old content can be localized by `POST /api/materials/:id/localize`. The operation consumes AI credits, is idempotent when the language already coincides and does not change existing IDs, relationships, evidence or sessions.
- `INCOMPLETE` represents a semantically correct response, but ambiguous or incomplete. `LOGICAL_BREAK` is reserved for contradiction, reverse causality or incorrect mechanism.
- Definition questions or simple recall questions are discarded and replaced by causal challenges.

## Docker

The local Compose starts API, worker, and PostgreSQL 17 in its own volume. Development values come from the versioned `.env.development`; the Gemini key and Supabase Auth URL come from the private `.env`. The second file takes precedence, and Compose passes `DEV_DATABASE_URL` to the API as `DATABASE_URL`, without using the private `.env` URL. The frontend remains outside Docker. The Supabase configured in `SUPABASE_URL` authenticates users; the application data is in the local PostgreSQL. After validating the token, the backend registers the ID authenticated in the local `auth.users` table to satisfy foreign keys. The Gemini key can be shared between environments; consider the consumption of the same quota.

```bash
docker compose --env-file .env --env-file .env.development up --build
```

The development database uses `127.0.0.1:5432`. The `test-db` service uses `127.0.0.1:5433` and is unique for integration testing. The URL of this database is in `.env.development`; `MIGRATION_TEST_REQUIRED=true` makes the suite fail if it is not loaded instead of skipping the tests. The suite erases schemas in the test database. The CI provides its own test database.

The production PostgreSQL is in Supabase. Only uploaded files stay in VPS's Docker `material_uploads` volume, so this volume should be included in the backup strategy until there is object storage.

When deleting a material, the database deletes its linked history and saves the key to the original file in `material_file_deletions` in the same transaction. The worker removes the file from the volume and deletes the pending deletion record; if the volume fails, the pending deletion record remains for further attempt. Keep the worker active and monitor old pending deletion records in this table before discarding the volume.

Each extraction job completed identifies a version. The API exposes `activeExtractionJobId` in `GET /api/materials/:id/status`; `null` indicates legacy concepts. A new extraction only activates the new concepts and relationships in the same transaction that concludes the job. Old concepts remain in the database for existing sessions, evidence, and files. If the new extraction fails or is cancelled, the previous version remains active. Migration 023 is additive; for an application rollback, preserve the added columns and use the previous image. Removing these columns requires evaluating historical references created after migration.

Migration 024 adds immutable context to new attempts at relation, application and retention: question version, used criteria, declared clues and ID of the previous attempt when one exists. Legacy attempts receive the `legacy` version and empty lists, without invented criteria. The API only accepts `previousEvidenceId` from the same account, material, activity, concept and relationship; `hintsUsed` requires `assisted=true`. The interface automatically connects a new attempt to the last of the same target and shows this link in the history. New evaluations use the `activity-v2` heading: understanding, relation, application and retention have different criteria, always accompanied by the assumptions anchored in the content. Contrast and whole-part relationships do not require causality.

To reproduce the local parsing baseline of reference materials, run `bun scripts/measure-phase2-baseline.ts`. The script outputs JSON by fixture with size, duration, editorial structure, payload and process memory variation. It does not call AI; tokens, cost and pedagogical extraction quality require a separate measurement with defined provider and expense limit. For this separate measurement in synthetic fixtures, use `PHASE2_LIVE_BENCHMARK=1 bun --env-file=.env scripts/measure-phase2-ai.ts`; `PHASE2_FIXTURE_OFFSET` and `PHASE2_FIXTURE_LIMIT` restrict the sample. The script does not record in the database, disables model fallback, does not print keys or user text and reports model, tokens, duration and anchor diagnosis. The call consumes the quota of the configured provider. Paste text accepts up to 500,000 characters per request. PDF, Markdown and TXT files accept up to 16 MiB; PDFs accept up to 800 pages. The text extracted from files does not have an additional ceiling by characters. The extraction divides long books into parts of up to 100,000 characters of indexed text and makes a call to Gemini on the part. Each indexed evidence span is capped at 1,600 characters, preferring sentence or word boundaries while preserving exact source offsets; this limit narrows citations but does not guarantee semantic correctness. Each call attempt consumes a credit; fallback and subsequent attempts can consume more. The final map selects up to the configured concept limit between the parts. Size limits, pages, time and memory can still prevent certain files from being imported.

## Deploy OCI and production protection

Backend and frontend are independent Git repositories. `development` integrates; `main` publishes. The frontend runs on Cloudflare Workers; API, worker and uploads are on OCI; PostgreSQL is in the Supabase. The backend image is published in GHCR by SHA. VM needs Docker Engine, Compose and HTTPS proxy. The proxy forwards to `127.0.0.1:3333` and preserves the SSE in `/api/events`.

Use Supabase URL **Session pooler** on port 5432 with `sslmode=require`; hide reserved characters from the password in the URL. API and worker use independent pools (`DATABASE_POOL_MAX=3` as initial operating value). From the backend, `bun run migrate` executes migrations with ledger/checksum and advisory lock; partial schema or altered historical migration should fail, never be silently reapplied. Migrations are additive and are not reversed by the rollback of the image.

On VM, copy `deploy/.env.example` to `/opt/masterme/.env` with `600` mode. Define `DATABASE_URL`, `SUPABASE_URL` HTTPS, `GEMINI_API_KEY`, `AI_GLOBAL_DAILY_CREDIT_LIMIT` and `AI_CREDITS_ENABLED`. `PUBLIC_APP_URL` uses the public frontend URL specified in `deploy/.env.example` by default; set it on VM only if the canonical HTTPS source changes. The example limits global consumption to 500 credits/day (up to five full free quotas); adjust this ceiling to the budget and demand before promotion. Leave `INFINITEPAY_HANDLE` and `METRICS_BEARER_TOKEN` empty on free release: payments and `/metrics` are disabled. A metric token of at least 32 characters should only be configured when one exists operational private collection. The `deploy/compose.yml` manifest fixes both as empty in this release, even if an old `.env` still has values; activating them requires a revised code change next to the frontend and operation. `OBSERVABILITY_DB_TIMEOUT_MS=1000` limits polling. Keys are only on VM, never on GitHub, frontend or log. GitHub's `production` environment requires `OCI_HOST`, `OCI_SSH_USER`, `OCI_SSH_KEY` and `OCI_KNOWN_HOSTS`. Get the host key by reliable channel; do not accept an unknown key in the workflow. Deploy SSH user needs controlled access to Docker.

Example Caddy; the metric rule comes ** before the proxy:

```caddyfile
api.seudominio.com {
  @operational path /metrics /metrics/*
  respond @operational 404
  request_body {
    max_size 18MB
  }
  reverse_proxy 127.0.0.1:3333
}
```

Publicly expose only 80/443. Apply rate limiting to the proxy for API, upload, SSE and webhook. The 18 MB ceiling interrupts multipart before the process; the API accepts up to 16 MiB file. Set timeout for slow uploads. InfinitePay webhook is public and accepts a maximum of 16 KiB in the API; it only triggers rereconciliation, and entitlement depends on confirmed `payment_check`. Do not require user session for this webhook. `/metrics` can only be collected by loopback/private network with an operational bearer token; without configured token returns `404`, incorrect token returns `401`.

CI requires PostgreSQL 17 disposable for integrations, dependencies audit, typecheck, testing, Compose validation, and production-only image smoke with read-only filesystem. CD repeats the gate before publishing to not depend on the order of parallel workflows. Automatic publication occurs only in `main`; manual execution in another branch must be refused. Deploy confirms `/ready` after migrations and updating of the API and the worker running. `/health` continues container liveness; this gate does not replace a point-to-point extraction test in the real environment.

First release: Migrate the database, publish backend, confirm `/health` in the domain and `/ready` via loopback, publish frontend, test upload, SSE, cancel and extract. If billing is active, make a controlled payment and confirm value, plan, unique entitlement and idempotent replay. Before release, check database backup, volume `material_uploads`, disk, memory, Gemini cost and previous image. Never copy secrets to the release evidence.

For manual rollback, use an earlier SHA without reverting schema:

```bash
cd /opt/masterme
MASTERME_IMAGE=ghcr.io/OWNER/masterme-backend:COMMIT_SHA docker compose --env-file .env -f compose.yml up -d
```

`deploy/deploy-and-verify.sh` saves the previous image in `/opt/masterme/.previous-image` and tries to restore it if the new API fails in `/ready`; the workflow keeps exit code of failure. Failure prior to readiness gate requires diagnostic and manual rollback. Financial data and additive migrations remain. In a cost incident, set `AI_CREDITS_ENABLED=false`; in an isolated checkout incident, remove `INFINITEPAY_HANDLE` without revoking existing entitlements. On the 1 GB VM, maintain API at 384 MiB, worker at 256 MiB and `EXTRACTION_CONCURRENCY=1` until measuring capacity. Preserve backups of the local volume; object storage is still pending evolution.

## Observability and operational response

JSON logs in stdout and local metrics do not send content, query, token, email, owner or Material/Request/Transaction IDs. `GET /health` checks the process; `GET /ready` queries the database with timeout; `GET /metrics` exposes series allowed with bearer. Local private collection:

```bash
curl --fail -H "Authorization: Bearer $METRICS_BEARER_TOKEN" http://127.0.0.1:3333/metrics
```

Initial objectives, subject to adjustment with real data: API without 5xx in 99.5% of requests in 30-day window; p95 below 2.5 s outside SSE; investigate queue with older job above 5 min and treat above 15 min as critical; investigate provider failures above 10% in 15 min. The plan only declares operational alerts when Prometheus/Grafana and destination of alerts are configured, collecting and validated in production.

- `/ready` in `503`: confirm `/health`, Session pooler and pool saturation; do not print `DATABASE_URL`. If it persists, stop deployment and restore image.
- AI failure/cost: separate operation and result, check logs per request ID and share in the provider. Disconnect new attempts with `AI_CREDITS_ENABLED=false` if necessary; reactivate after controlled test.
- Stalled extraction: check PENDING/PROCESSING/FAILED, Job Age, Worker Memory and Disk. Lease is resumed after five minutes; do not perform concurrent manual SQL. Restart only worker if API is healthy.
- Billing pending: check pending orders and connectivity with InfinitePay; never force `PAID` into the database. Use authenticated rereconciliation after provider confirmation. Removing handle prevents new checkouts.
# Book chapter checkpoints

Book uploads with a named top-level source section are extracted one chapter at a time. The worker commits each completed chapter and records its checkpoint in `processing_job_units`. If a later chapter fails, completed chapters remain readable; automatic and manual retries reuse the same job and skip completed chapters. Cancelling stops future chapter commits. The status, retry, and cancel endpoints require the material owner. Migration `033_chapter_checkpoints` is additive; rollback disables the chapter path while preserving the table and existing concepts.

Migration `034_question_versions` adds immutable learning objectives and question snapshots. New evaluated evidence links to the exact prompt, rubric, source excerpt, and extraction job through a question version. Old evidence remains readable with a null link. `GET /api/learning/materials/:materialId/questions` returns current concepts with their objectives and answered question versions, including a fallback objective for legacy concepts. Rollback stops new writes and reads from these tables while retaining their history.

Migration `035_attempt_context` distinguishes Study, focused Drill, and delayed Review evidence, backfilling existing review-linked records. `GET /api/learning/materials/:materialId/drill` selects an active concept, recent uncontested gap, source, criterion, and an application question without spending AI credits. Submitting that question through `POST /api/learning/activities/answers` with `attemptContext: "DRILL"` uses the same grounded evaluator and records the attempt separately from Study and Review. Rollback can ignore the new column while retaining the evidence rows.

Migration `036_task_project_link` adds an optional owner-checked project reference to Practice tasks. Creating or editing a linked task validates that the project belongs to the same material and account. Deleting a project clears its task reference; task completion never changes project or learning evidence. The column is additive and can be ignored on rollback.
